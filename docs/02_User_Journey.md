# 02. User Journey
## 첫 실행부터 다시 배우러 오는 순간까지

**버전:** v0.1 · 경험 설계 초안  
**기준일:** 2026-10-04  
**문서의 역할:** 기능 목록보다 먼저, 사용자가 어떤 흐름으로 이해와 성장을 경험할지 정한다.  
**기준 문서:** [01. Product Concept](01_Product_Concept.md)

> 첫 실행의 목표는 사용자를 분류하거나 회원으로 전환하는 것이 아니라, 한 가지 개념을 이해하고 다음 학습의 이유를 발견하게 하는 것이다.

---

## 1. 경험 설계의 전제

사용자는 투자에 대한 관심이나 경험이 있지만, 자신의 지식 수준을 정확히 설명하기 어려울 수 있다. 자신을 완전한 초보자로 보지 않을 수도 있고, 반대로 용어를 모른다는 사실을 부담스러워할 수도 있다.

따라서 처음부터 “당신의 금융 점수는 몇 점”이라고 평가하기보다, 구체적인 질문을 풀어보면서 현재 필요한 학습을 발견하게 한다. 긴 가입 과정이나 필수 진단 테스트는 초기 흐름의 전제로 두지 않는다.

아래의 7일 여정은 사용 모습을 상상하기 위한 시나리오다. 실제로 7일 연속 접속해야 하거나, 정해진 날짜에만 레슨이 열리는 구조를 뜻하지 않는다. 사용자는 한 번에 더 배우거나 며칠 쉬었다 이어갈 수 있다.

## 2. 첫 실행: 한 번의 작은 학습을 끝낸다

### 2.1 서비스의 약속을 이해한다

첫 화면은 기능 설명보다 사용자가 얻을 변화에 집중한다.

> **주식을 사는 법은 알지만, 화면의 숫자는 아직 낯설다면.**  
> 짧은 학습과 퀴즈로 투자 개념을 하나씩 연결해보세요.

주요 행동은 ‘첫 학습 시작하기’, 보조 행동은 ‘어떤 내용을 배우는지 보기’ 정도로 단순하게 둔다. 첫 버전에서 개인화 경로가 없다면, 마치 개인별 분석이 완료된 것처럼 표현하지 않는다.

게스트 시작을 우선 제안한다. 계정 생성과 기기 간 동기화는 첫 이해 경험의 필수 조건이 아니다.

### 2.2 앞으로 배울 지도를 짧게 본다

첫 코스는 **‘주가를 넘어 기업의 숫자 이해하기’**를 제안한다.

```text
주식 한 주 → 주가 → 시가총액
                      │
기업의 매출과 이익 → EPS → PER → 숫자를 함께 해석하기
```

지도는 코스의 위치 관계를 보여준다. 복잡한 전체 금융 스킬트리, 잠긴 영역 수십 개, 완료까지 남은 긴 학습량을 처음부터 보여주지 않는다.

추천 시작점은 제공하되, 이미 아는 내용은 둘러보거나 다른 레슨을 선택할 수 있게 한다. 선행 지식이 필요할 때는 잠금보다 짧은 복습 안내를 우선한다.

### 2.3 작은 질문으로 학습을 시작한다

첫 레슨의 질문 예시는 다음과 같다.

> “내가 산 주식 한 주는 무엇을 의미할까?”

상황을 본 뒤 짧은 설명과 예시를 따라간다. 첫 레슨에서 회사 분석 전부를 가르치려고 하지 않는다. 하나의 핵심 구분을 남기고, 다음에 주가와 시가총액을 배우는 이유를 만든다.

초기 세션은 대략 3~5분을 목표로 하되, 실제 읽기와 풀이 시간을 보고 조정한다.

### 2.4 퀴즈와 해설을 경험한다

정답을 고르면 근거를 짧게 확인한다. 오답을 고르면 선택한 답이 왜 그럴듯해 보였는지 짚고, 핵심 차이를 설명한다.

표현은 ‘틀렸으니 처음부터 다시’보다 다음 방향을 지향한다.

> “헷갈릴 수 있어요. 이 둘은 무엇을 보유하게 되는지가 달라요. 핵심 차이를 보고 다른 예시로 확인해볼게요.”

실제 문구는 문항 내용에 맞게 작성한다. 공통 칭찬이나 위로만 반복하지 않는다. 즉시 같은 정답을 다시 누르는 것과 새 예시를 이해하는 것은 구분한다.

### 2.5 성과와 다음 이유를 확인한다

결과 화면에는 세 가지를 남긴다.

| 요소 | 전달할 내용 |
| --- | --- |
| 오늘 이해한 것 | “주식 한 주가 무엇을 의미하는지 확인했어요.”처럼 구체적인 학습 결과 |
| 진행과 보상 | 레슨 완료, 경험치, 작은 성장 연출 |
| 다음 연결 | “이제 한 주의 가격과 회사 전체의 주식시장 평가액을 구분해볼까요?” |

첫 레슨 완료만으로 ‘투자 실력 상위권’ 같은 평가를 하지 않는다. 한 번의 성공은 해당 학습을 해봤다는 신호이지, 광범위한 금융 역량을 검증한 결과가 아니다.

## 3. 첫 일주일의 예시 여정

기준 코스는 [03. Learning System](03_Learning_System.md)의 L01~L08이다. 하루에 두 레슨이 등장하는 날도 여러 번에 나눠 사용할 수 있다. 다음 표는 학습 흐름을 설명하며, 출석 조건이나 개발 일정을 뜻하지 않는다.

| 시점 | 사용자의 질문 | 제안하는 경험 | 남기고 싶은 변화 |
| --- | --- | --- | --- |
| 첫 방문 | “이 앱에서 무엇을 배울 수 있지?” | L01: 주식 한 주의 의미, 첫 퀴즈와 완료 경험 | “내가 이미 해본 행동을 개념으로 설명할 수 있네.” |
| 두 번째 방문 | “주가가 낮으면 회사도 더 싼가?” | L02~L03: 주가와 시가총액, 간단한 비교 사례 | “한 주의 가격과 전체 규모는 다르구나.” |
| 세 번째 방문 | “회사가 많이 팔면 이익도 큰가?” | L04: 매출과 이익을 구분하는 사례 | “매출과 순이익을 같은 숫자로 보면 안 되겠네.” |
| 네 번째 방문 | “회사의 이익을 한 주 기준으로 볼 수 있나?” | L05: EPS, 이전 레슨 연결 카드 | “기업의 이익과 내가 보는 주당 숫자가 연결되는구나.” |
| 다섯 번째 방문 | “PER은 왜 주가만 보는 것과 다르지?” | L06: 주가와 EPS를 함께 비교 | “주가가 낮은 것과 PER이 낮은 것은 다르네.” |
| 여섯 번째 방문 | “PER이 달라졌다면 무엇이 변한 걸까?” | L07: 조건을 바꾼 문제와 필요한 개념 복습 | “공식을 외우는 대신 무엇이 바뀌었는지 볼 수 있겠다.” |
| 일곱 번째 방문 | “새로운 회사에도 배운 내용을 적용할 수 있나?” | L08: 통합 사례, 판단 가능한 것과 추가 정보 구분 | “이 숫자로 알 수 있는 것과 모르는 것을 구별할 수 있다.” |

첫 코스를 마친 뒤 다음 코스가 준비되지 않았다면 복습과 학습 기록으로 자연스럽게 마무리한다. 존재하지 않는 콘텐츠를 무한히 해금되는 것처럼 보이게 하지 않는다.

## 4. 다시 방문했을 때의 홈

재방문 홈의 첫 질문은 “오늘 무엇부터 하면 좋을까?”다. 정보를 많이 모아놓은 대시보드보다, 바로 실행할 수 있는 학습 행동이 잘 보여야 한다.

```text
현재 코스와 마지막 학습 위치
          ↓
이어 학습하기
          ↓
다시 확인하면 좋은 개념
          ↓
최근 이해한 내용과 성장 기록
```

이어 학습하기와 복습 중 어느 것을 크게 보여줄지는 실제 사용 반응으로 조정한다. 둘 다 노출하더라도 무엇이 기본 행동인지 불명확해지지 않게 한다.

설명 없이 낮은 점수만 보여주기보다는 “PER 문제에서 EPS가 바뀌는 경우를 다시 확인해보세요”처럼 구체적인 안내를 사용한다.

## 5. 대표 화면의 책임

이 표는 화면 개수나 라우팅 구조를 고정하지 않는다. 작은 버전에서는 여러 역할을 한 화면에 합쳐도 된다.

| 화면 또는 영역 | 주된 역할 | 피할 것 |
| --- | --- | --- |
| 시작 안내 | 누구를 위한 앱인지, 첫 행동이 무엇인지 설명한다. | 긴 가입 절차, 근거 없는 맞춤 분석 |
| 홈 | 이어 할 학습과 복습을 안내한다. | 점수·배너·메뉴가 학습 행동을 가리는 구성 |
| 코스 지도 | 앞뒤 개념과 현재 위치를 보여준다. | 전체 학습을 불필요하게 잠그거나 과도한 분기를 만드는 구성 |
| 레슨·퀴즈 | 질문, 개념, 예시, 확인을 자연스럽게 잇는다. | 긴 정의의 나열, 해설 없는 정오답 표시 |
| 결과 | 배운 내용, 보상, 다음 연결을 정리한다. | 경험치만 남고 학습 내용은 사라지는 화면 |
| 학습 기록 | 배운 개념과 다시 볼 내용을 확인하게 한다. | 짧은 퀴즈로 산출한 정밀한 금융 능력 점수 |

오답 복습은 초기에는 홈과 결과 화면의 작은 영역으로도 충분하다. 별도의 대규모 ‘오답노트’ 기능이 꼭 필요한 것은 아니다.

## 6. 정상 흐름 외에 챙길 경험

### 이미 아는 내용이 나온다

사용자는 레슨을 빠르게 읽거나 다른 레슨을 선택할 수 있다. ‘알고 있어요’를 눌렀다는 이유만으로 숙련도까지 확인된 것으로 기록하지 않는다. 선행 개념이 부족한 경우에는 해당 설명으로 이동할 수 있게 한다.

### 같은 관계에서 반복해서 헷갈린다

같은 문제를 계속 재출제하기보다 필요한 앞 개념으로 연결한다. 예를 들어 PER 해석에서 EPS를 혼동한다면 EPS 설명을 짧게 다시 보게 한다. MVP에서는 미리 작성한 연결과 해설만으로도 이 경험을 구현할 수 있다.

### 정답을 맞혔지만 자신이 없다

선택적으로 해설을 더 보거나 복습 대상으로 남길 수 있게 한다. 처음부터 복잡한 확신도 점수 체계를 만들 필요는 없다. 테스트에서는 “왜 이 답이라고 생각했나요?”를 물어 추측과 이해를 구분한다.

### 중간에 앱을 닫는다

마지막으로 확인된 학습 진행을 보존한다. 완벽한 문장 단위 복원보다, 재진입했을 때 이미 마친 내용을 불필요하게 반복하지 않는 것이 중요하다. 보상이 중복 지급되거나 완료된 레슨이 사라지지 않아야 한다.

### 며칠 쉬었다 돌아온다

끊어진 출석 기록을 먼저 강조하지 않는다. “지난번에는 EPS를 배웠어요. 짧게 떠올리고 PER로 이어갈까요?”처럼 학습 맥락을 복구한다. 출석 기능을 도입하더라도 복귀를 방해하는 벌점 구조는 지향하지 않는다.

### 저장에 문제가 생긴다

진행이 저장되지 않았는데 완료된 것처럼 단정하지 않는다. 가능한 복구나 재시도를 안내한다. 한 기기 저장 방식으로 테스트한다면 다른 기기와 연동되지 않으며, 저장 공간 정리 시 기록이 사라질 수 있다는 한계를 알린다.

### 글이나 움직임을 편하게 보기 어렵다

색상만으로 정오답을 구별하지 않고 텍스트도 함께 제공한다. 작은 글씨나 시간 제한에 의존하지 않으며, 보상 애니메이션 때문에 다음 학습이 지연되지 않게 한다. 표현 방식은 선택한 플랫폼의 접근성 기능을 고려한다.

## 7. 앱이 사용하는 말투

친근하지만 사용자를 어린아이처럼 대하지 않는다. 잘못된 답을 꾸짖지 않으며, 한 번의 정답을 과도하게 치켜세우지도 않는다.

| 상황 | 지향하는 표현 | 피하려는 표현 |
| --- | --- | --- |
| 오답 | “주가와 회사 전체 규모를 나눠서 보면 이해하기 쉬워요.” | “기초도 모르셨네요.” |
| 레슨 완료 | “주가와 EPS를 연결해서 PER을 계산해봤어요.” | “이제 저평가 종목을 찾을 수 있어요!” |
| 복습 | “다른 숫자에서도 같은 관계가 보이는지 확인해볼까요?” | “숙련도가 떨어졌습니다. 즉시 복습하세요.” |
| 복귀 | “지난번 학습부터 이어가보세요.” | “연속 기록 실패! 보상이 사라졌어요.” |

특정 회사나 자산을 칭찬하는 문구보다 사용자가 이해한 관계를 강조한다.

## 8. 첫 사용성 테스트에서 볼 장면

관찰자는 설명을 많이 하기보다 사용자가 스스로 다음 행동을 찾을 수 있는지 지켜본다.

| 관찰 질문 | 설계를 바꿔야 할 신호 |
| --- | --- |
| 첫 화면만 보고 앱의 목적을 설명할 수 있는가? | 종목 추천이나 실제 투자 게임으로 오해한다. |
| 도움 없이 첫 학습을 시작할 수 있는가? | 프로필·등급·메뉴 사이에서 헤맨다. |
| 해설을 읽고 다른 예시를 풀 수 있는가? | 정답 위치는 기억하지만 개념을 설명하지 못한다. |
| 결과에서 무엇을 배웠는지 기억하는가? | 경험치와 배지만 기억한다. |
| 다음 레슨을 선택하는 이유가 있는가? | 보상 외에는 다음 내용을 배울 이유를 말하지 못한다. |

숫자나 클릭 경로만으로 결론 내리지 않는다. 사용자가 이해한 내용을 직접 말해보는 장면과 함께 판단한다.
