# 04. MVP
## 작게 만들되, 학습의 한 바퀴는 완성한다

**버전:** v0.1 · 첫 구현 범위 제안  
**기준일:** 2026-10-04  
**문서의 역할:** 첫 버전의 범위, 검증 질문, 완료 기준, 개발 시 판단 원칙을 정한다.  
**기준 문서:** [01. Product Concept](01_Product_Concept.md), [03. Learning System](03_Learning_System.md)

> MVP는 기능이 적은 퀴즈 앱이 아니라, ‘궁금증 → 개념 이해 → 확인 → 성장 → 다음 학습’의 한 바퀴를 실제로 경험할 수 있는 버전이다.

---

## 1. 첫 버전에서 확인할 것

첫 버전은 다음 세 가지 가설을 검증하기 위해 만든다.

| 검증 가설 | 확인 방법 | 가설이 약할 때 먼저 바꿀 것 |
| --- | --- | --- |
| 연결된 순서가 개념 이해에 도움이 된다. | 배운 내용을 다른 예시에서 구별·계산·설명하는지 본다. | 레슨 순서, 선행 설명, 예시 구성 |
| 짧은 레슨과 해설이 혼자 학습하기에 충분하다. | 개발자의 설명 없이 첫 학습을 마칠 수 있는지 본다. | 문장 길이, 화면 흐름, 오답 해설 |
| 성장 표시가 다음 학습의 동기를 만든다. | 다음 레슨 선택과 재방문 이유를 관찰한다. | 결과 화면, 다음 질문, 보상 표현 |

단기간의 사용성 테스트만으로 시장성, 장기 학습 효과, 유료 전환 가능성까지 입증했다고 판단하지 않는다.

## 2. 제안하는 MVP의 경계

### 콘텐츠 범위

첫 코스는 **‘주가를 넘어 기업의 숫자 이해하기’**로 제안한다. [03. Learning System](03_Learning_System.md)의 L01~L08을 기본안으로 삼되, 분량은 고정하지 않는다.

최초 프로토타입에서는 L01~L03처럼 연결되는 일부 레슨으로 전체 사용 흐름을 먼저 완성한다. 콘텐츠와 UI가 잘 맞는지 확인한 다음 코스를 확장한다. 처음부터 수십 개 레슨을 작성하거나 금융 전 영역을 펼치지 않는다.

### 제품 범위

첫 검증은 한 기기에서 학습을 시작하고, 중간에 나갔다 돌아와 이어 할 수 있으면 된다. 플랫폼은 사용자가 접근하기 쉬운 형태와 기존 개발 환경을 보고 선택한다.

실제 시세, 종목 정보, 증권계좌 연동이 없어도 가상 기업과 검토된 교육용 데이터로 핵심 경험을 만들 수 있다. 계정 시스템과 서버가 반드시 먼저 있어야 한다고 가정하지 않는다.

## 3. 꼭 포함할 경험

| 영역 | 최소한으로 필요한 경험 | 범위 조절 원칙 |
| --- | --- | --- |
| 시작 | 앱의 목적을 이해하고 첫 레슨을 바로 시작한다. | 게스트 진입 우선. 필수 가입·긴 진단은 두지 않는다. |
| 코스 지도 | 무엇을 배우며 지금 어디에 있는지 확인한다. | 전체 금융 스킬트리 대신 현재 코스만 보여준다. |
| 레슨 | 상황, 개념, 예시를 순서대로 읽는다. | 한 레슨에 핵심 질문 하나를 중심으로 구성한다. |
| 퀴즈와 해설 | 답을 선택하고 이유를 확인한다. | 객관식·간단한 계산 등 구현 부담이 낮은 형식부터 사용한다. |
| 결과와 보상 | 배운 내용, 완료 표시, 기본 XP·성장 표시를 본다. | 정확한 등급 수와 경험치 공식은 조정 가능하게 둔다. |
| 학습 기록 | 완료한 레슨과 다시 볼 개념을 확인한다. | 별도 대시보드보다 홈·결과 화면의 간단한 표시도 가능하다. |
| 복습 | 오답 개념의 설명이나 준비된 다른 예시로 돌아간다. | 자동 맞춤 학습 엔진 없이 작성된 연결부터 제공한다. |
| 이어하기 | 재진입 후 이전 학습과 기록을 이어간다. | 기기 간 동기화보다 한 기기에서의 안정성을 먼저 확인한다. |

레슨 완료는 정답률 100%를 강제하는 의미가 아니다. 설명과 확인 활동을 마쳤다면 다음 학습으로 이어갈 수 있고, 헷갈린 개념은 복습 대상으로 따로 남긴다.

XP와 활동 레벨을 우선 구현하더라도 이를 ‘실제 투자 역량’으로 표현하지 않는다. 개념 이해 표시는 퀴즈·변형 문항 등 실제 확인한 범위를 벗어나지 않는다.

## 4. 첫 버전에 포함하지 않는 것

| 보류할 기능 | 지금 제외하는 이유 | 다시 검토할 조건 |
| --- | --- | --- |
| 필수 가입·소셜 로그인·기기 간 동기화 | 첫 이해 경험을 검증하는 데 선행 조건이 아니다. | 기록 보존과 여러 기기 사용 요구가 실제로 반복된다. |
| 개인별 정밀 진단·자동 경로 생성 | 충분한 콘텐츠와 검증된 문항이 먼저 필요하다. | 시작 지점이 맞지 않아 이탈하는 문제가 뚜렷하다. |
| 전체 스킬트리·캐릭터 상점·리그 | 콘텐츠 부족을 복잡한 보상 구조로 덮을 수 있다. | 기본 학습 루프와 재방문 이유를 확인했다. |
| AI 튜터·실시간 문제 생성 | 정확성·비용·콘텐츠 통제의 검토가 추가된다. | 정적 해설로 해결되지 않는 질문이 축적됐다. |
| 실시간 뉴스·시세·보유 종목 분석 | 외부 데이터와 운영 범위가 커진다. | 개념의 현실 연결이 실제 핵심 요구로 확인됐다. |
| 모의투자·경제 시뮬레이션 | 별도 게임 규칙과 평가 설계가 필요하다. | 기본 개념 학습 이후 적용 연습 수요가 확인됐다. |
| 결제·구독·기관 관리 화면 | 사용 가치 검증과 수익화 검증은 다른 단계다. | 실제 반복 사용과 구매 주체의 요구를 확인했다. |

‘보류’는 영구 제외나 다음 출시 약속이 아니다. 후보와 검증 방식은 [05. Product Ideas](05_Product_Ideas.md)에 남긴다.

## 5. 구현 순서 제안

### 단계 A. 작은 구간을 끝까지 연결한다

L01~L03 정도의 실제 원고와 퀴즈를 준비한다. 시작 안내, 레슨, 해설, 결과, 보상, 재진입까지 연결한다. 이 단계에서 모든 화면을 완벽하게 디자인하거나 플랫폼 전체를 추상화하지 않는다.

임시 문구와 무의미한 예시만으로 구현하면 학습 경험을 판단하기 어렵다. 적은 분량이라도 실제로 읽고 배울 수 있는 내용을 사용한다.

### 단계 B. 작은 테스트로 방향을 교정한다

기획의 계기가 된 사용자와 비슷한 입문자에게 직접 사용해보게 한다. 가능하다면 주식을 사본 사람과 관심만 있는 사람을 모두 만나본다.

특히 첫 행동을 찾는지, 해설로 오해가 풀리는지, 결과에서 배운 내용을 기억하는지 확인한다. 이 단계에서 발견한 큰 문제를 해결한 뒤 콘텐츠 양을 늘린다.

### 단계 C. 하나의 짧은 코스를 완성한다

L04~L08 등 연결되는 레슨을 확장한다. 코스 마지막에는 새 사례에서 개념을 함께 해석해보는 활동을 둔다. 최소 일부 핵심 개념에는 복습용 다른 예시를 준비한다.

### 단계 D. 재방문과 이해의 유지 여부를 본다

같은 코스를 반복해서 눌렀을 때 보상이나 진도가 어긋나지 않는지 확인한다. 사용자 테스트에서는 며칠 뒤 짧은 변형 문항과 설명 질문으로 무엇이 남았는지 살펴본다.

단계마다 날짜를 고정하지 않는다. 완료 기준은 화면 수보다 해당 경험이 실제로 작동하는지에 둔다.

## 6. 첫 사용자 테스트 제안

초기에는 예를 들어 5~8명 정도의 작은 테스트로 이해 문제와 사용성 문제를 찾을 수 있다. 이 규모는 시장을 대표하는 표본이 아니라, 제품을 고치기 위한 출발점이다.

### 사용 전

투자 경험과 모르는 개념을 어떻게 해결하는지 짧게 묻는다. 가능하면 본인이 최근 헷갈렸던 용어를 하나 설명해보게 한다. 투자 금액, 계좌 정보, 보유 종목 전체를 수집할 필요는 없다.

핵심 개념 몇 개에 대해서는 배경 지식을 확인한다. 이 결과는 테스트 분석용이며, 첫 앱 화면에서 정밀한 능력 점수로 보여줄 필요는 없다.

### 사용하는 동안

진행 방법을 대신 알려주기보다 막힌 위치를 기록한다. 정답 여부뿐 아니라 문제를 어떤 의미로 읽었는지, 해설에서 무엇이 풀렸는지 확인한다.

### 사용 직후와 이후

학습 때와 다른 숫자·상황을 제시한다. 맞혔는지와 함께 이유를 말할 수 있는지 본다. 자발적으로 다시 사용했는지, 테스트 요청 때문에 돌아온 것인지도 구분한다.

며칠 뒤 후속 확인을 진행한다면 참여 동의와 연락 방법을 별도로 정한다. 앱에 계정·알림 시스템을 먼저 구현하지 않고도 테스트를 진행할 수 있다.

## 7. 무엇을 측정하고 어떻게 해석할까?

초기에는 복잡한 분석 도구 없이 관찰 기록과 최소한의 학습 데이터로도 시작할 수 있다.

| 관찰 항목 | 정의의 출발점 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 첫 레슨 완료 | 첫 레슨을 시작한 사람 중 확인 활동과 결과까지 도달한 사람 | 읽지 않고 넘긴 완료와 실제 이해는 다르다. |
| 새 예시 적용 | 학습 예시와 다른 문항에서 관계를 올바르게 사용했는지 | 동일 정답을 재선택한 기록과 섞지 않는다. |
| 설명 가능성 | 사용자가 핵심 차이나 관계를 자신의 말로 설명하는지 | 정답을 외운 표현인지 추가 질문으로 확인한다. |
| 해설의 도움 | 오답 이후 새 예시에서 혼동이 줄었는지 | 같은 문항을 맞힌 것만으로 해설 효과를 확정하지 않는다. |
| 다음 학습 선택 | 한 레슨 뒤 자발적으로 다른 레슨을 시작하는지 | 진행자의 안내나 필수 테스트 절차로 이동한 것은 구분한다. |
| 재방문 | 미리 정한 관찰 기간 안에 다시 학습하는지 | 테스트 참여를 위한 재접속과 자발적 사용을 구분한다. |

숫자를 정리할 때는 ‘70%’만 쓰기보다 ‘10명 중 7명’처럼 분모를 함께 남긴다. 소수 테스트에서 나온 수치를 전체 사용자 성과로 일반화하지 않는다.

방문률이 낮고 학습 효과는 있다면, 바로 게임 기능을 늘리기 전에 사용자가 공부할 이유와 코스 주제가 맞는지 살펴본다. 반대로 방문률은 높지만 이해가 늘지 않는다면 보상보다 콘텐츠와 문항을 먼저 고친다.

## 8. 사용 가능한 첫 버전의 완료 기준

다음은 기술 명세가 아니라, 사용자에게 건넬 수 있는 상태인지 확인하는 점검 기준이다.

| 구분 | 확인할 상태 |
| --- | --- |
| 시작과 진행 | 설명 없이 첫 학습을 시작하고, 다음 행동을 찾을 수 있다. |
| 콘텐츠 | 제공하는 레슨의 학습 목표·사례·정답·해설이 서로 일치한다. 가상 데이터와 가정이 표시되어 있다. |
| 오답 경험 | 오답에도 이유를 볼 수 있고, 필요한 개념을 다시 확인할 수 있다. |
| 기록 | 종료·재진입 후 확인된 진도가 유지된다. 같은 완료 동작으로 XP가 의도치 않게 중복 지급되지 않는다. |
| 성장 표현 | 활동 보상과 이해 확인이 구별되고, 확인하지 않은 역량을 인증하지 않는다. |
| 코스 연결 | 앞뒤 개념의 관계와 다음 학습의 이유가 드러난다. |
| 오류 처리 | 저장이나 로딩 실패를 숨기지 않고 다음 행동을 안내한다. |
| 읽기와 조작 | 선택한 주 사용 기기에서 텍스트·버튼·퀴즈를 무리 없이 읽고 조작할 수 있다. |
| 학습 검증 | 적어도 핵심 개념에 대해 학습 문항과 다른 확인 사례가 준비되어 있다. |

완료 기준을 충족해도 금융 콘텐츠의 검토와 개인정보·배포 관련 점검을 생략한 채 정식 출시 준비가 끝났다고 보지는 않는다.

## 9. 콘텐츠와 데이터의 운영 원칙

콘텐츠와 화면을 완전히 뒤섞어두기보다, 레슨·문항·해설을 수정하기 쉬운 형태로 관리한다. 다만 이를 위해 처음부터 별도 관리자 시스템을 만들 필요는 없다. 파일 기반인지 다른 저장 방식인지는 구현 환경에 맞춰 선택한다.

학습 기록은 필요한 범위만 저장한다. 실제 자산·수익률·계좌·실명은 핵심 경험에 필요하지 않다. 사용자 답변을 수집한다면 목적과 보관 범위를 먼저 정하고, 외부 분석 도구나 AI에 보내는 범위를 자동으로 넓히지 않는다.

청소년 대상 공개 서비스, 계정, 결제, 외부 데이터 수집을 추가할 때에는 해당 조건에 필요한 검토를 진행한다. 관련 요건을 이 초안에서 확정하거나 면제된 것으로 가정하지 않는다.

## 10. 지금 정하지 않는 기술 결정

웹·네이티브 앱, 프레임워크, 상태 관리, 서버 유무, 인증, 데이터베이스, 분석 도구, 배포처는 여기서 고정하지 않는다. 기존 프로젝트가 있다면 먼저 그 환경을 확인한다.

구현 시에는 다음 방향을 따른다.

**되돌리기 쉬운 선택은 작은 구현으로 검증하고, 사용자 기록·비용·개인정보처럼 되돌리기 어려운 선택은 이유를 드러내고 결정한다.**

XP 값, 레슨 순서, 화면 구성은 수정하기 쉬워야 한다. 반면 계정 연동이나 외부 서비스 도입은 단지 문서에 후보로 등장했다는 이유로 추가하지 않는다.

## 11. Codex 작업을 시작할 때 전달할 문구

다음 문구는 이 문서 묶음을 프로젝트의 `docs/`에 넣은 뒤 사용할 수 있는 작업 지시 초안이다.

```text
먼저 docs/01_Product_Concept.md부터 05_Product_Ideas.md까지 읽어주세요.
이 문서들은 완성된 기술 명세가 아니라 제품 방향성과 MVP 범위의 초안입니다.

핵심은 투자 경험은 있으나 개념이 정리되지 않은 사용자가,
짧은 학습과 퀴즈를 통해 개념을 연결하고 성장을 확인하는 경험입니다.

기존 프로젝트가 있다면 구조와 실행 환경을 먼저 확인해주세요.
04_MVP.md를 기준으로 가장 작은 실행 가능한 학습 흐름부터 구현해주세요.
초기에는 L01~L03처럼 연결되는 일부 레슨으로 한 바퀴를 완성하고,
작동하는 결과를 확인하면서 콘텐츠와 화면을 확장해주세요.

활동 XP와 개념 이해를 같은 점수로 표현하지 마세요.
문항에는 정답뿐 아니라 해설과 앞 개념으로 돌아가는 연결이 필요합니다.
가상 사례와 학습용 가정은 실제 시세나 확정적 투자 판단처럼 표현하지 마세요.

05_Product_Ideas.md의 기능은 명시적으로 범위에 넣기 전에는 구현하지 마세요.
AI, 로그인, 실시간 뉴스, 결제, 복잡한 스킬트리를 기본 요건으로 가정하지 마세요.

아직 정하지 않은 기술·화면 세부사항은 기존 환경과 변경 용이성을 기준으로 제안해주세요.
가볍고 되돌리기 쉬운 선택은 합리적으로 진행하되,
범위·외부 비용·개인정보 처리에 큰 영향을 주는 변경은 먼저 설명해주세요.

문서와 구현이 달라질 때는 무엇을 왜 바꿨는지 짧게 기록해주세요.
구현하지 않은 기능이나 검토하지 않은 금융 콘텐츠를 완료된 것처럼 표시하지 마세요.
```
