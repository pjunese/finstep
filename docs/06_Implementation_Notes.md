# 첫 구현 기록 · 2026-10-07

## 선택과 범위

- 사용자 요청에 따라 iOS와 Android를 함께 지원하는 Flutter 앱으로 시작했다. 기존 앱 코드는 없었으며 로컬 Flutter·Xcode·Android SDK가 준비되어 있었다.
- Figma의 Product Orange 화면·타이포그래피·색상·원본 SVG를 기준으로 구현했다. 플랫폼 상태 표시줄/홈 인디케이터와 화면 모서리 테두리는 운영체제가 맡는다.
- 먼저 L01~L03의 학습 루프를 구성한 다음, 사용자가 제공한 데이터에 동일한 구조를 적용해 L01~L08 및 문항 32개를 연결했다.
- 개정된 MD에서 생성한 JSON을 앱에 번들한다. 기본 학습은 핵심 한 화면과 작은 숫자 예시로 진행하며, 긴 원고와 출처는 선택해서 펼쳐본다.
- 아직 존재하지 않는 ETF·경제 후속 코스는 학습 지도에 표시하지 않는다. 로그인·AI·뉴스·결제·계좌 연동은 추가하지 않았다.

## 문서 및 시안에서 구체화한 동작

- 레슨당 학습 3문항, 별도 복습 1문항. 오답은 같은 레슨 복습 큐에 추가한다.
- 복수 선택 문항은 정답 집합 전체가 일치해야 정답이다. L08 문항에는 원문의 C·D회사 표와 가정을 함께 표시한다.
- 첫 응답, 해설을 본 동일 문항 재응답, 처음 접하는 복습 문항, 이미 접한 복습 문항을 구분한다. 이미 본 문제로 독립적인 이해가 확인됐다고 표시하지 않는다.
- 최초 완료만 30 XP. 오답도 완료 가능. 복습·재학습은 0 XP. 개념별 정밀 숙련도나 투자 실력 점수를 만들지 않는다.
- 읽기 위치, 숫자 실험 값, 선택지, 해설 단계, 문제 위치, 완료, 북마크를 저장한다. 다른 레슨을 시작해도 기존 미완료 레슨의 진행을 보존한다.
- 저장 작업을 기다린 뒤 다음 상태를 반영한다. 연속 탭이 저장/보상을 중복시키지 않게 막는다. 저장 실패 시 이전 기록과 화면 단계를 유지하고 재시도할 수 있다.
- Figma의 '발행주식수' 표기는 제공 원고의 `C_SHARES_OUTSTANDING` 정의를 따라 '유통주식수' 및 '계산에 사용하는 주식 수'로 명확히 했다.
- MD 내부 오개념 태그는 사용자 화면에서 '헷갈리기 쉬운 점'으로 표시한다. `educational_example_only` 산식의 인용 누락은 변환 단계에서 형식만 보정한다.

## 확인 범위와 남은 작업

2026-10-07 로컬 검증 결과:

- `dart run tool/import_content.dart --check`: 원고와 번들 데이터 일치, 8개 레슨·15개 개념·32문항.
- `flutter analyze --no-pub`: 진단 없음.
- `flutter test --no-pub --reporter expanded`: 19개 통과. 모든 레슨 완료/XP 중복 방지, 복수 선택, 저장·복원·실패·손상 데이터, 개념 검색, 작은 화면·큰 글자를 포함한다.
- iPhone 16e 시뮬레이터(iOS 26)와 Pixel 7 Android 에뮬레이터: 첫 학습 → 오답 해설 → 완료 → 파일에서 기록 복원 → 학습 지도·개념 연결 흐름 통과.
- Android 일반 진입점의 release APK 빌드·설치·실행 성공. 최종 APK는 테스트 진입점이 아닌 `lib/main.dart`로 빌드했다.
- iOS 일반 진입점의 simulator debug 빌드·설치·실행 성공. 실기기용 release 빌드도 `--no-codesign`으로 성공했다. 실제 iPhone 설치·서명은 수행하지 않았다.
- 실행 화면을 확인했으며 Android 일반 앱은 OS 캡처로 상태 표시줄·하단 버튼 여백도 확인했다. 통합 테스트 캡처는 일부 화면 경계를 정확히 반영하지 않을 수 있어 외부 미리보기에는 OS 캡처를 사용한다.

콘텐츠 자동 검사는 개념 연결, 답안 집합, 해설 존재, 통합 사례 산식을 확인한다. 원문의 검토 상태를 독립적인 금융 전문가 검수 완료로 취급하지 않는다. 정식 배포 전 콘텐츠 표현 검토와 실제 입문자 사용성 테스트가 필요하다.

배포 식별자, 최종 앱 아이콘, 배포용 Android 서명 키와 Apple 개발자 팀/프로비저닝, 스토어 메타데이터는 출시 단계에서 확정한다. 현재 빌드는 개발·검증용이다.


## 짧은 핵심 학습으로 개정 · 2026-10-07 · v0.1.1

사용자 피드백: 긴 설명을 기본 경로에서 강제로 읽게 하지 않고, 핵심·예시·비유를 짧게 보여준다. 금액도 억·조 단위 대신 천 원~10만 원 정도로 줄인다.

- 필수 읽기 3~4장을 핵심 한 화면으로 줄였다. 상세 본문·정확한 회계 기준·출처는 ‘자세히 알아보기’에서 선택한다.
- 8개 레슨의 핵심 문장과 예시를 MD의 `brief`로 관리한다. 7개 숫자 활동은 `exercise`의 세 가지 값만 사용하며 결과가 정수이고 10만 이하인지 검사한다.
- 원천 개념 MD의 큰 숫자 예시와 퀴즈 MD의 32문항을 수정했다. 상세 설명의 계산 예시도 함께 줄여 숫자가 엇갈리지 않게 했다. 이전 MD는 `work/short-learning-before/`에 보관했다.
- 퀴즈 해설은 한 문장을 먼저 보여주고, 전체 선택지의 이유·관련 개념·전체 표는 선택해서 본다. 통합 문제는 질문에 필요한 행만 표시한다.
- 가중평균 계산, 희석 EPS, EV의 세부 사항을 기본 퀴즈에서 요구하지 않는다. 정의와 주의점은 선택형 상세 설명에 남긴다.
- 기존 진도 파일을 읽으면 완료·XP·선택지·북마크를 유지한다. 예전 긴 읽기 위치는 새 핵심 화면으로, 범위를 벗어난 숫자 조작 단계는 새 세 단계 범위로 옮긴다. 새 답안 이벤트에는 콘텐츠 버전을 함께 기록한다.
- 테스트에 선택형 설명을 열어도 진도가 변하지 않는지, 모든 레슨이 한 화면 뒤 예시로 가는지, 작은 숫자 계산, 기존 기록 호환성을 추가했다.

개정 검증: 자동 테스트 19개, 정적 검사, MD→JSON 일치 검사를 통과했다. iPhone 16e와 Android 에뮬레이터에서 새 필수 흐름·상세 보기의 선택성·숫자 변경·기록 복원을 확인했다. 실기기용과 시뮬레이터용 네이티브 캐시가 섞인 iOS 검증 오류는 생성된 빌드 캐시를 정리한 뒤 재검증해 해소했다.
