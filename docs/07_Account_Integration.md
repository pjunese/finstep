# 마이페이지와 로그인 연결 준비 · 0.2.0

2026-10-07 사용자 요청에 따라 화면·기기 내 프로필·인증 연결 구조를 먼저 구현하고 실제 SNS 인증 환경은 후속 작업으로 남겼습니다.

## 현재 동작

- `마이`: 닉네임·프로필 색상, 완료 레슨, 저장 개념 수, XP·레벨, 학습 기록·오답 복습·저장 개념 바로가기.
- 프로필 수정: 1~16자 닉네임과 네 가지 색상. 저장 성공 후 화면 값을 바꿉니다.
- 설정: 프로필, 계정 관리, 데이터 보관 안내, 학습 FAQ, 앱 정보·오픈소스 라이선스.
- 로그인·회원가입 진입 화면: Google·카카오·네이버·Apple. 미연결 서비스는 `준비 중`이며 누르면 안내합니다. 게스트 학습을 계속할 수 있습니다.
- 앱 시작: 양쪽 OS의 네이티브 시작 화면, Flutter 자료 준비 화면, Orange 단계 모양 아이콘. 인위적인 대기 시간을 추가하지 않습니다.

학습 기록은 기존 `finstep/progress-v1.json`, 프로필은 별도 `finstep/profile-v1.json`에 저장합니다. 두 파일은 Application Support 아래에 있으며 프로필 수정이 학습 파일을 덮어쓰지 않습니다. 저장 실패 시 직전 데이터를 유지하고, 읽기 실패 시 덮어쓰기를 막고 재시도를 제공합니다.

실제 계정 생성, OAuth 요청, 서버 동기화, 기기 간 복원은 아직 제공하지 않습니다. 운영 앱은 `UnconfiguredAuthGateway`를 사용하므로 모든 로그인이 준비 상태입니다. 가짜 계정이나 임의 토큰을 만들지 않습니다.

## 코드 연결 지점

`lib/state/account.dart`의 `AuthGateway`를 실제 인증 서비스로 구현한 뒤 `lib/main.dart`의 `Bootstrap`에서 주입합니다.

| API | 실제 구현의 책임 |
| --- | --- |
| `availableProviders` | SDK·클라이언트 설정·서버 검증이 모두 준비된 공급자만 반환 |
| `restore()` | 안전하게 보관된 세션을 복원·검증한 뒤 공개 계정 정보 반환 |
| `signIn(provider)` | 공급자 인증 → 서버 검증/계정 생성 → 검증된 계정 반환 |
| `signOut()` | 현재 앱 세션 폐기 완료 후 반환 |
| `deleteAccount()` | 필요 시 재인증 후 계정과 개인 데이터의 서버 삭제 완료 후 반환 |

`AccountController`는 요청 중복 방지, 취소, 오류, 미지원 공급자, 로그인 복원, 로그아웃·탈퇴 상태를 관리합니다. 취소는 오류 안내 없이 게스트 상태를 유지합니다. 실패한 로그아웃·삭제를 성공으로 표시하지 않습니다. `AccountUser`에는 공개 식별 정보만 담고 토큰은 넣지 않습니다. 테스트용 성공 응답은 `test/`에만 있습니다.

## 실제 연결 단계에서 해야 할 일

1. 배포용 앱 식별자와 인증 서버를 정합니다. 지금 식별자는 개발용 `dev.finstep.finstep`입니다. 특정 서버 제품은 아직 선택하지 않았습니다.
2. 각 공급자 개발자 콘솔에 iOS·Android 앱, 콜백, 서명 정보를 등록합니다. 공개 클라이언트 식별자와 비밀키를 구분하고 서버 비밀키는 앱 번들·JSON·저장소에 넣지 않습니다.
3. SDK와 검증 서버를 구현합니다. 앱 콜백만 보고 계정을 신뢰하지 않고 검증된 서버 세션으로 확정합니다. 세션 갱신·만료와 플랫폼의 안전한 저장소를 연결합니다.
4. 신규 가입 약관·개인정보 안내와 동의 흐름, 실제 문서 링크를 연결합니다. 공급자 공식 버튼·브랜드 규정도 이 단계에서 반영합니다. 현재 중립 버튼은 준비 화면입니다.
5. 계정별 학습 데이터 영역과 기기 간 동기화를 구현합니다. 게스트 기록을 어느 계정에 합칠지, 중복 XP를 어떻게 막을지, 다른 계정으로 전환할 때 어떤 기록을 보여줄지 정해야 합니다. 현재 기기 기록을 아무 계정에나 자동 업로드해서는 안 됩니다.
6. 실제 로그아웃·회원 탈퇴 서버 API를 연결하고, 서버 데이터와 기기 데이터의 처리 범위를 확정합니다. 현재 계정 관리의 확인·실패 UI는 연결을 위한 구조이며 미연결 앱에서 계정 삭제는 실행되지 않습니다.
7. 공급자별 첫 가입·재로그인·취소·네트워크 실패·세션 만료·콜드 스타트 콜백·탈퇴·다른 계정 로그인 및 양쪽 OS를 검증한 뒤 공급자를 활성화합니다. 동기화가 완료되기 전에는 기록 복원을 약속하는 문구를 표시하지 않습니다.

## 브랜드 자산

`assets/icons/brand-mark.svg`는 코드로 만든 임시 브랜드 마크입니다. iOS 앱 아이콘과 LaunchImage, Android 구형 런처 PNG는 macOS에서 `swift tool/render_brand.swift`로 다시 생성합니다. Android 적응형 아이콘·시작 로고는 `android/app/src/main/res/drawable/`의 벡터 자산을 사용합니다. Figma 최종 로고가 확정되면 함께 교체합니다.

## 검증 범위

프로필 저장·재실행 복원·쓰기 실패·손상 파일 보호, 로그인 미설정·취소·오류·중복 탭·잘못된 계정 응답, 마이페이지 이동, 320px와 글자 1.5배 레이아웃을 자동 테스트합니다. 네이티브 통합 테스트는 임시 저장소에서 학습 → 프로필 저장 → 실제 파일 재읽기 → 로그인 준비 상태 → 게스트 학습 복귀를 확인합니다. 공급자 SDK·실제 인증 서버의 검증은 후속 연결 단계에 속합니다.
