# 0.5.0 · 학습 목표, 복습 추천, 출시 준비

기준일: 2026-10-13. 현재 콘텐츠는 기존 핵심 50개·150문항·홈 질문 50개를 유지합니다.

## 이번 구현

- 홈의 ‘오늘의 학습’에서 진행량과 다음 학습을 확인합니다.
- 목표는 기본 하루 1개이며, 홈·마이페이지에서 1/2/3개로 바꿉니다.
- 새 개념 또는 복습을 마지막 해설까지 마쳐야 1개입니다. 같은 개념은 새 학습과 복습을 합쳐 하루 한 번만 셉니다. 홈 한입 질문이나 중간 종료는 포함하지 않습니다.
- 목표를 넘겨도 계속 학습할 수 있습니다. 기존 레슨 선택·이어하기·저장 기능을 유지합니다.
- 복습 날짜가 된 개념을 먼저 추천하고, 그중 오답이 남은 개념을 우선합니다. 추천이 없으면 다음 미완료 개념을 제안합니다.
- 완료 화면에 오늘 진행량과 다음 복습 추천 날짜가 표시됩니다.

## 복습 규칙

| 상황 | 처리 |
| --- | --- |
| 새 학습을 완료 | 다음 날 다시 추천 |
| 다른 날 복습을 모두 맞히고 남은 오답도 없음 | 완료일에서 3일 → 7일 → 14일 → 30일 뒤로 간격 확대 |
| 복습 중 틀리거나 남은 오답이 있음 | 다음 날 다시 추천, 간격 초기화 |
| 같은 날 정답 복습을 반복 | 복습 날짜를 더 뒤로 미루지 않음 |
| 예전 버전에 완료 기록만 있음 | 과거 날짜를 만들지 않고 복습 후보로 표시 |
| 추천일 전 다시 보고 싶음 | 복습 화면에서 자유롭게 시작 가능 |

이 일정은 학습을 다시 시작하기 위한 단순한 추천 규칙입니다. 이해도 진단이나 개인별 기억력 예측은 아닙니다. 현재 앱 안에서만 안내하며 기기 알림은 보내지 않습니다. 본 학습 최초 완료의 30 XP 규칙은 그대로이며, 복습·재학습은 XP를 추가하지 않습니다.

## 기록 보존

- 완료·XP·하루 진행량·복습 날짜를 같은 저장 작업으로 반영합니다. 저장 실패 시 완료로 표시하거나 실적을 올리지 않습니다.
- 선택적 `studyPlan`의 자체 버전은 1입니다. 기존 진행 파일 스키마 2와 이전 과정의 `legacy`를 유지합니다.
- 날짜는 기기의 현지 달력 날짜를 사용합니다. 앱을 켜 둔 채 자정이 지나거나 다음 날 다시 활성화하면 화면을 갱신합니다.
- 기기 시간이 뒤로 바뀌더라도 저장된 복습 날짜를 과거로 이동시키지 않습니다. 서버 시간 검증이나 여러 기기의 동기화는 아직 없습니다.
- 일일 완료 내역은 최근 90개의 활동 날짜만 보관하고, 개념별 복습 일정과 완료·XP는 유지합니다.
- 모르는 데이터 버전·잘못된 날짜·중복 개념 등 손상된 기록은 자동 초기화하지 않습니다.

## Android 배포 설정

- `targetSdk = 36`. 확인한 [Google Play 공식 요구사항](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)에 따르면 2026-08-31부터 신규 앱과 업데이트는 API 36 이상을 대상으로 해야 합니다. 실제 제출 시 다시 확인합니다.
- HTTP 평문 통신을 허용하지 않도록 `usesCleartextTraffic=false`를 지정했습니다. 현재 앱은 오프라인 콘텐츠와 로컬 기록을 사용합니다.
- 기존 release의 debug 서명 대체를 제거했습니다. `preReleaseBuild`에 서명 검사를 연결해 키가 없으면 중단합니다. `debug.keystore` 및 `androiddebugkey`도 거부합니다.
- `android/key.properties.example`은 형식만 제공합니다. 실제 `android/key.properties`, 키 파일, 비밀번호는 공유·커밋하지 않습니다. 키는 이번 작업에서 생성하지 않았습니다.
- 키 설정 뒤 `flutter build appbundle --release --target lib/main.dart`로 AAB를 만듭니다. [Flutter 공식 Android 배포 안내](https://docs.flutter.dev/deployment/android)를 참고합니다.

## 검증

- 정적 분석 오류 없음, 전체 자동 테스트 **57개 통과**(기존 44개 + 목표·복습 관련 13개). MD 원본과 앱 데이터 일치 검사도 통과했습니다.
- Pixel 7 Android 에뮬레이터와 iPhone 16e iOS 26 시뮬레이터에서 목표 변경 → 학습 완료 → 디스크 기록 복원 → 다음 날 추천 → 복습 완료 흐름을 통과했습니다. 기존 홈·오답·프로필·로그인 준비 화면도 함께 확인했습니다.
- 손상된 파일, 저장 실패, 중복 완료, 이전 기록, 자정·연도 변경, 기기 시간 역행, 큰 글자·좁은 화면을 자동 테스트로 확인합니다.
- 실제 `preReleaseBuild`가 서명 미설정으로 중단되는 것을 확인했습니다. 이는 의도한 보호 동작입니다.
- Android 개발용 APK의 네이티브 ELF 적재 구간과 ZIP 페이지 정렬을 16 KB 기준으로 검사했습니다. 실행한 에뮬레이터의 페이지 크기는 4 KB이므로 **16 KB 환경에서 실제 실행한 검증은 아닙니다**. 서명된 최종 AAB와 16 KB 환경 확인은 출시 전에 필요합니다. [Android 공식 16 KB 안내](https://developer.android.com/guide/practices/page-sizes)
- 통합 테스트는 앱의 실제 기록과 분리된 임시 디렉터리를 사용합니다.
- 검증 후 `lib/main.dart`를 대상으로 Android debug APK와 iOS 시뮬레이터 앱을 다시 빌드·설치해 일반 홈 화면이 실행되는 것을 확인했습니다. 스토어용 release 빌드는 아직 만들지 않았습니다.

## 출시 전 남은 작업

1. **출시 식별자·계정·서명 확정**: 현재 `dev.finstep.finstep`, Play Console 소유 계정과 업로드 키, iOS 개발자 팀을 확정합니다.
2. **실제 로그인·서버 연결**: 공급자 설정, 로그인 취소·실패·세션 만료, 계정 연결·탈퇴, 게스트 기록 이전과 동기화 충돌을 구현·검증합니다. 현재 버튼은 ‘준비 중’입니다.
3. **실기기 및 배포 검증**: Android 16 KB 환경, 다양한 Android 실기기, 최종 AAB 내부 테스트, iPhone 실기기·TestFlight를 확인합니다. 개발용 APK나 시뮬레이터 통과만으로 배포 검증을 대신하지 않습니다.
4. **스토어 제출 자료**: 실제 데이터 처리에 맞춘 개인정보처리방침·지원 연락처·Play Console 데이터 보안 응답·콘텐츠 등급·소개·스크린샷을 준비합니다. 실 로그인 등 수집 기능이 추가되면 함께 갱신합니다.
5. **콘텐츠 최종 검수**: 50개 개념과 150문항의 표현·정답·해설을 검수하고, 운영 중 수정 절차를 정합니다.

푸시 알림과 원격 콘텐츠 관리·분석 기능은 아직 없습니다. 도입 여부를 정한 뒤 필요한 권한·설정·데이터 처리까지 함께 구현합니다.
